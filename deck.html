The Challenge

Why Automated Task Generation is Critical

The bottleneck in evaluating and fine-tuning frontier coding agents

02 / 06
1. The Need for Real-World AI Benchmarks
Frontier coding LLMs (Claude 3.5 Sonnet, GPT-4o, DeepSeek-Coder) cannot be evaluated accurately with synthetic LeetCode-style puzzles. They require authentic open-source codebases with complex dependency trees, real bug reproductions, and strict verification suites.
2. The Manual Authoring Bottleneck
Handcrafting isolated container tasks (SWE-bench / Terminal-Bench style) takes experienced software engineers 3 to 5 hours per task. Pinned environments, dependency resolution, and oracle solutions must be maintained by hand.
3. The Harbor v0.25.x Standard
Harbor introduces standardized, sandboxed task execution for Terminal-Bench 2.0. Every problem requires a strict layout: `task.toml` metadata, `instruction.md`, isolated `Dockerfile`, `solve.sh` oracle script, and a fail-to-pass `test.sh` verification harness.
Our Solution
An autonomous pipeline that ingests verified baseline commits from pallets/click, automatically mining bug patches to synthesize 100% compliant Harbor container packages ready for evaluation.

Harbor v0.25.x Standardized Architecture

Strict directory contracts ensuring full evaluation reproducibility

03 / 06
tasks/<task-name>/ ├── instruction.md # Clear prompt provided to agent ├── task.toml # TOML manifest (timeouts, resources) ├── environment/ │ └── Dockerfile # Python 3.11 sandbox @ baseline e0d8b58 ├── solution/ │ └── solve.sh # Oracle gold patch demonstrating fix └── tests/ ├── test.sh # Verification harness runner └── test_verifier.py # Pytest fail-to-pass test suite
The Scoring Contract
`tests/test.sh` executes inside the container sandbox. Upon test completion, it writes a numerical score (1.0 for pass, 0.0 for fail) directly to /logs/verifier/reward.txt.
Automated Synthesis Workflow
1. Baseline Pinning: Clones pallets/click at verified commit e0d8b58.
2. Task Synthesis: Generates instructions, Dockerfile, and unified diff patches.
3. Fail-to-Pass Verification: Verifies that baseline fails tests and oracle patch succeeds.
4. Harbor Linter Validation: Automatically inspects TOML schemas and file contracts.

Why pallets/click is the Ideal Foundation

Python's most reliable CLI architecture with clean test isolation

04 / 06
Industry Significance
`pallets/click` is the foundation of modern Python CLI software (used by Flask, Black, Pipenv, and AWS CLI). It powers millions of production workflows, making bug fixes in Click representative of real-world software engineering.
Clean Dependency Architecture
Unlike repositories requiring heavy C/C++ build tools, Click is written in pure, high-quality Python. This allows lightweight, fast Docker images (python:3.11-slim) that spin up in under 5 seconds during benchmark agent runs.
Rich, Reproducible Bug Surface
Click's modular codebase separates parameter typing (types.py), option parsing (parser.py), and command group trees (core.py). This provides clear, unambiguous problem statements suitable for evaluating coding agents.
Verified Baseline Commit
Pinned to commit e0d8b5847e2ef30fa27ce803405c19be38d17ba7, guaranteeing that all generated tasks run against a deterministic, reproducible environment without version drift.

05 / 06
Task 1: click-paramtype-custom-formatting
Target: types.py • Difficulty: Medium
Problem: When a custom ParamType subclass omits name, invalid inputs throw an unhandled exception or leak None.
Resolution: Implements fallback to class name in metavar formatting and error reporting.
Task 2: click-hide-sensitive-prompt-default
Target: core.py • Difficulty: Medium
Problem: When an option has both hide_input=True and a default value, Click displays the secret default in plaintext in the terminal.
Resolution: Masks the secret default (e.g. [******]) while maintaining functional default usage.
Task 3: click-nested-group-subcommand-resolve
Target: core.py • Difficulty: Hard
Problem: In nested command groups where subcommands share prefixes, fuzzy prefix matching erroneously raises ambiguity errors for exact matches.
Resolution: Enforces immediate exact match precedence before executing prefix matching algorithms.
Verification Summary
Each task contains its own verified oracle script (solve.sh) and fail-to-pass test suite (test.sh) ensuring complete evaluation reliability for Innodata.
